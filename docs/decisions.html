0041Style rules: one base colour per object, shade and highlight by ruleAccepted

Accepted (2026-11-21)

  • Five style rules, for every new piece of art in 2D and 2.5D, for Create and the AI maker, and for games as they are next worked on:
  • 1. One base colour per object, from the palette (0040). Its shade and highlight are not picked by hand: they come from the base by a fixed rule (shade: mixed toward the palette's shadow purple-grey; highlight: mixed toward white). palette.js gives all three, so a creator names one colour. In 3D the light makes the shade, and the rule is tuned to match it.
  • 2. One shade tone and one soft highlight per object, flat fills. Light from the upper left, shade on the lower right.
  • 3. Gradients, grain and haze only in the big background layers (sky, mist, far hills), never inside objects.
  • 4. Simple, chunky shapes for anything that might become 3D (round bushes, faceted mountains, cube heads, simple props). Fine detail belongs to painted pieces, which never need a 3D version (0038's "3D only where needed").
  • 5. The thin ink edge on characters and touchables only (0038), never on scenery. Not done: fewer palette colours (worlds would look alike), and no redraw of finished art (Pop Party and the other games stay as they are).

Owner's change (2026-11-21): rework the existing games too: The owner prefers the existing games reworked onto the palette and the five rules, rather than waiting until each is next touched. Plan item U11, after U10 (the rule in code) lands: first the shared painted asset library (every game draws from it), then Pop Party (the rule is tuned to its balloons, so it changes least; extra care, the owner approves before and after), then the small games (Sleepy Bear, Leaf Pile, Stack It High, Sky Painter, Animal Gym, Keep It Up, Pterry Flight, Save the Harvest, the Cubion story), one game per step with before and after pictures from the sweep tool. The two big ones (Last Known Position, about 680 hand-picked colours, and Tower Defense, about 140) come after the Phase 1 release, when they are finished (0021). Raw colour codes removed this way lower the ratchet baseline.

0040The master palette: one named list of colours for 2D and 2.5DAccepted

Accepted (2026-11-21)

  • One master palette in app/src/games/assets/palette.js, shown on docs/palette.html. Groups: touchables (8), favourites (8), sky and light, the meadow green ladder, warm earth, shade/ink/paper, interface accents, and the Phase 1 world sets.
  • Touchables are the brightest objects. Scenery never uses them.   • Games use colour names, never raw codes, so the palette can be tuned later in one place:
  • 1. Orlis supplies the palette while a game runs (assets.color('touch.mint')); store and Create games do not carry their own copy.
  • 2. Names never change once published: values may be tuned, colours added, old ones retired gently.

Accepted (2026-11-21), including the April 30, 2027 release date

  • 3D games move like a paper stage. A guided camera, side-on or slightly from above, follows the player through small stage-like areas. Characters and most props are painted pieces that flip like a card when they turn (a quick squash, then the mirror image). Real 3D only for the ground, walls and things you go around (0038).   • True 3D is a later phase. To keep that door open at no cost now: the camera is one swappable piece of code (each game picks fixed or guided, later free), and game logic works in world positions, never screen positions.
  • The FPS is a game the owner makes with Claude's help and puts on the store. It stays family-safe: a splat, foam or water blaster, not weapons (recommended). Other people can copy it and change a few parts (the map from kit pieces, colours, rules, targets) but not the camera, controls or core feel. Creating a new FPS from scratch is not in Create. "Copy a store game and change some parts" is a new Create feature for a later phase.
  • Release date: April 30, 2027, quality first (accepted by the owner 2026-11-21). The May 28 date was set for the toon redraw of Pop Party, which 0037 dropped, and the guided phone camera is less work than first person. The date moves back before the quality bar moves.

Pop Party remains the one perfected game (0033).

Owner's addition (2026-11-21): the names: The game types are called 2D (the painted look, 0038), 3D-Limited (this decision: a 3D stage with painted pieces, a guided camera and flipping characters) and, in a later phase, 3D (true 3D: free camera, first person). Owner's change (2026-11-21): 2.5D, not "3D-Limited": The middle type is called 2.5D (the owner's choice, replacing "3D-Limited" above). The names are 2D, 2.5D and, later, 3D. 0038Two looks, one family: painted 2D for 2D games, a painted-style 3D sibling for 3D gamesAccepted

Accepted (2026-11-20); supersedes 0036

  • 2D games use the painted look (Pop Party's: painted skies, faceted mountains, haze, cel shading with one tone, soft highlights).
  • 3D games use its 3D sibling, built from the same rules: the same painted sky and sun as a backdrop, the same palette, haze that softens far things, faceted mountains and round bushes, one shade tone and soft matte highlights on objects, no dark outlines, touchables the brightest things. First test: spike3d/siblings.html.
  • What makes them one family: Cubo and the cube-headed avatars, the palette and sky, the shapes, the UI kit and HUD (shared by both), the sounds and the motion.

Owner's addition (2026-11-20): 3D is "as little as needed": 3D games prefer painted 2D pieces and use real 3D only where it makes sense. The rule: a thing is 3D only if the player walks on it, goes around or inside it, bumps into it, or sees it turn (ground, hills, walls, buildings, vehicles, things with physics, the characters). Everything else stays a painted 2D piece standing in the world: the sky, sun and clouds, mountains far away, grass, flowers, petals, distant trees, effects (confetti, sparkles), signs and decals. Far things can be painted even if near things are 3D. Why: it keeps the painted charm, it is lighter to draw, and there is less 3D art to make. Care needed: painted pieces must be tinted by the scene's light so they sit in it, and games whose camera looks steeply down should use 3D for what would otherwise look flat from above. Each kit asset says whether it exists as a painted piece, a 3D model, or both, and the game uses the painted one unless the rule says 3D.

Owner's addition (2026-11-20): what keeps the siblings close: Agreed rules for both looks: 1. One avatar, drawn two ways. Each cube-headed avatar is made once as a 3D model; 2D games use painted sprites rendered from it, 3D games use the model. 2. The same motion. One shared motion file: squash and stretch, idle breathing, pop timing and easing curves, used by both. 3. One palette. 3D colours come only from the master palette that the 2D pieces use (palette still to be approved). 4. The same light side. The sun is upper left in both; shadows fall to the right and highlights sit upper left. On trial, owner to judge in spike3d/siblings.html (buttons 4 to 7): a clearer light from the sun's side, paper texture printed on 3D surfaces, the thin ink edge around balloons and bushes (this would replace "no dark outlines" above if kept), and soft hand-made wobble on shapes. The same effects, sounds, HUD, transitions and loading screen are shared as already stated.

Owner's verdict on the trial (2026-11-20): Keep the thin ink edge (button 6): 3D objects that matter (balloons, bushes, characters, touchables) get the same thin dark edge as the 2D pieces, around their outline only. This replaces "no dark outlines" above. Dropped: the stronger sun-side light (button 4; rule 4, the sun upper left in both looks, still stands), paper texture on surfaces, and the hand-made wobble.

Owner's addition (2026-11-20): no grass on the floor: 3D scenes do not scatter painted grass tufts on the ground: it looks too busy. The ground keeps its painted texture (soft patches, paths), with a few flowers at most.

0032Joining without typing: scan the QR, or match three picturesAccepted

Accepted (pictures, not a QR secret)

  • Scan the QR on the TV (the phone's camera app opens the pad page). The QR carries a one-time secret, so there is nothing to type.
  • Fallback: a picture code. If the QR cannot be scanned (a phone already on the page, a camera that will not focus), the TV shows three pictures in a row from the asset library (for example balloon, cat, star) and the phone shows a grid of nine; the player taps the same three in order. 9 x 9 x 9 = 729 combinations, a new set each session, five wrong tries and the phone waits a minute: plenty on a home network.
  • After the first join nothing changes from 0028: the phone keeps its token, the Box trusts it, and it rejoins by itself.
  • Not chosen: the grown-up confirms each new phone on the TV (adds a step every time a cousin visits); a wave at the camera to let a phone in (fun, but it makes joining depend on the camera, and pads must work without it).

Owner's answer (2026-11-20): Joining is by the three pictures. 0031How Peekaboo Garden is builtAccepted; the phone view is a guided camera, not first person

Accepted; the phone view is a guided camera, not first person (0039)

  • One world, written once: games/peekaboo/world.js holds the garden as data (ground, hedges, the shed, hiding places of three kinds: bush, big flower pot, tall grass), plus collisions and "is this point hidden". The host, the TV view and the phone view all import it, so the two screens cannot disagree.
  • The host (on the Box) holds the truth: the round clock, the lanterns, the hider's hiding state, and "found". The hider's phone moves its own player at once (it feels instant) and sends position and heading 20 times a second; the host checks it against the world (speed, walls) and is the one that decides found. Loose on cheating, strict on fairness for kids.
  • The seekers: each tracked seeker's hand points at the TV; the host turns that screen point into a spot on the ground (a ray from the TV camera onto the garden floor). That spot is a lantern. This is how a tracked hand targets a 3D world, for overview views.
  • Found: the hider is found when inside a lantern's light for about 0.6 seconds while not fully hidden. Hiding places lower how quickly that fills; moving near a bush makes it rustle on the TV (a fair, kid-friendly hint).
  • What each screen shows: the TV shows the whole garden from a fixed, high three-quarter view, the lanterns and the rustles, never the hider unless lit or found. The phone shows the hider's first-person view, including the lantern light sweeping across the garden, so hiding is tense and fun. In Phase 1 there is one pad, so the host sends the same state to it; per-seat filtering comes with more pads.
  • Messages: phone to host: move (position, heading, crouch), hide or leave a hiding place. Host to phone, 15 to 20 times a second: the lanterns, the clock, the hiding meter, found. Events: found, round over.
  • Characters: the hider appears on the TV only when found, as their avatar made into a paper puppet (a short reveal: pops out, waves). Seekers are shown as lantern lights and their avatars at the garden's edge. This keeps Phase 1's character animation small.
  • Round: 90 seconds a round; the hider wins by not being found; then roles can swap. Gentle: no fail sounds, a giggle and a wave.

0028Sessions and seats in codeAccepted

Accepted (except the join code, see 0032)

  • A session (in the host's JavaScript) has: the game, a join code (4 letters, new for each session), the TV's role, and seats.
  • A seat is { n, kind: 'tracked' | 'pad', who (a kid or grown-up profile on the Box), colour, state: 'live' | 'away' | 'empty', device }. Games only ever see seats, never "the person at the camera" or "the phone".
  • The game manifest says what it needs: tracked seats [min, max], pad seats [min, max], the pad program, and what the pad must draw (controller or view3d). Pop Party: tracked 1 to 4, pads 0 to 4 (a pad player drags a finger to move a mitt). Peekaboo Garden: tracked 1 to 2 (seekers), pads exactly 1 (the hider, view3d).
  • Joining: first time, the phone shows the code from the TV (or scans the QR, which carries it); the phone then keeps a device token and the Box remembers it (trusted, listed in Settings, removable). After that, rejoining is automatic, to the same seat.
  • Dropping: a seat a game cannot do without (Peekaboo's hider) pauses the game with a friendly "Waiting for Mia's phone"; it resumes by itself on rejoin; after 2 minutes the TV offers to end the round. Seats a game can do without (Pop Party's extra pads) just go quiet.
  • Who is who: a phone picks a profile from the Box's own list of kids and grown-ups (pictures, no typing).
  • Kid profiles move to the Box (0011): a name or nickname, avatar and progress stored by Orlis Play; the server keeps only grown-up accounts and what the family owns. Existing kid profiles are moved once, then deleted from the server.

0027The pad link: Orlis Play runs a small local hub; the game host is a client of itAccepted
  • A small hub in Orlis Play's Rust side listens on the home network (one port, 47880): it serves the pad page over HTTP and carries WebSocket messages. It is a dumb relay: no game logic, no rules, no join decisions.
  • The game host is a WebSocket client of the hub, connecting from the WebView to 127.0.0.1 with a secret only the app knows. Pads connect over the home network. The hub tags what each pad sends with its connection id and delivers what the host addresses.
  • Join and trust decisions live in the host's JavaScript, not in Rust, so the same host code can later run on an iPad or phone (0005) with any relay underneath.
  • One protocol, versioned JSON messages, written down in docs/specs/pad-protocol.md (the spec is part of this decision).
  • A Node copy of the hub (tools/pad-hub.mjs, about 100 lines) for development and automated tests, so joins, drops and rejoins are tested headlessly with Playwright, without phones.
  • Plain http:// and ws:// on the home network. Consequence accepted: no secure context on the phone, so no tilt sensors and no wake lock API (0019 already accepted that; the pad keeps itself awake another way, see the spec).
